# Лабораторная работа 02. Контролируемая сборка iperf3 из исходного кода

[Подготовка, пакеты, полные конфиги и уточнения](README.md) · [Общие материалы и ключи](../../PREPARATION.md)

Ниже все шаги руководства лабораторных v4 от 10.08.2026 с сохраненными
командами и ожидаемыми результатами. Сначала выполните подготовку в README:
она определяет адреса, значения переменных и различия ОС. Команды выполняются
по одной, на указанной машине; альтернативные ветки ОС не выполняются вместе.
В командах по умолчанию X=10/Y=20/Z=30, lab NIC=enp0s8, зоны internal/external/public.
Их необходимо сопоставить с реальными NIC/zone по README. Имена unit и web-user
по умолчанию Rocky; для Debian/Ubuntu используйте соответствия из README.
Выводы — образцы, а не протокол запуска на вашей ВМ.

Цель лабораторной работы: пройти полный цикл доверенной сборки: проверка архива, зависимости, configure, test и установка в /usr/local.

Стенд: одна Linux-ВМ с доступом к репозиторию пакетов; архив iperf3-X.Y.tar.gz и SHA256SUMS предоставляет преподаватель.

Сценарий: в репозитории нет требуемой версии iperf3. Слушатель собирает выданный преподавателем архив, проверяет его целостность и устанавливает программу в /usr/local.

Планируемый результат: собранная версия iperf3 запускается из /usr/local/bin, проходит локальный client/server-тест, а файлы сборки не перезаписывают системный пакет.

## Ограничения и безопасность

Важно: не запускайте make install, если checksum или make check завершились ошибкой.

Важно: не используйте prefix /usr: этим каталогом управляет пакетный менеджер.

## Ход выполнения

## Шаг 1. Установить требуемые пакеты

Установите компилятор, make и заголовки OpenSSL из репозитория своей ОС. Ветки команд не смешиваются. Установите пакеты только для выбранного семейства ОС. Ключ -y подтверждает пакетную транзакцию без дополнительного запроса.

```bash
# RHEL-like
sudo dnf group install -y 'Development Tools'
```

## Шаг 2. Установить требуемые пакеты

Установите пакеты только для выбранного семейства ОС. Ключ -y подтверждает пакетную транзакцию без дополнительного запроса.

```bash
sudo dnf install -y openssl-devel
```

## Шаг 3. Обновить метаданные пакетов

Обновите локальные метаданные репозиториев до установки пакетов; это действие не устанавливает и не обновляет сами пакеты.

```bash
# Debian/Ubuntu
sudo apt update
```

## Шаг 4. Установить требуемые пакеты

```bash
sudo apt install -y build-essential pkg-config libssl-dev
```

cc --version и make --version возвращают версии.

## Шаг 5. Создать каталог с заданными правами

Перед распаковкой сверьте имя и checksum с переданным манифестом. Команда install создает каталог или копирует файл сразу с заданными владельцем и mode: -d выбирает каталог, -m задает права, -o/-g — владельца и группу.

```bash
install -d -m 0750 ~/src/lpic103-iperf3
```

## Шаг 6. Скопировать файл или каталог

Выполните одну операцию с данными и метаданными; checksum/diff подтверждают результат, а dry-run не изменяет приемник.

```bash
cp "$REPO/generated/downloads/iperf"/iperf-3.21.tar.gz ~/src/lpic103-iperf3/
```

## Шаг 7. Скопировать файл или каталог

```bash
cp "$REPO/generated/downloads/iperf"/SHA256SUMS ~/src/lpic103-iperf3/
```

## Шаг 8. Перейти в рабочий каталог

```bash
cd ~/src/lpic103-iperf3
```

## Шаг 9. Проверить контрольную сумму

```bash
sha256sum -c SHA256SUMS
```

Ожидаемый вывод и результат:

```text
<файл>: OK
```

Для архива получено OK.

## Шаг 10. Обработать архив

configure проверяет зависимости и запоминает prefix; компиляция и тесты выполняются без root. Выполните одну операцию с данными и метаданными; checksum/diff подтверждают результат, а dry-run не изменяет приемник.

```bash
tar xf iperf-3.21.tar.gz
```

## Шаг 11. Перейти в рабочий каталог

```bash
cd iperf-3.*
```

## Шаг 12. Подготовить сборку

Выполните один этап сборки или проверки зависимостей и переходите дальше только при нулевом exit status.

```bash
./configure --prefix=/usr/local
```

Ожидаемый вывод и результат:

```text
config.status: creating Makefile
Configuration completed; exit status = 0
```

## Шаг 13. Выполнить этап сборки

```bash
make -j"$(nproc)"
```

Ожидаемый вывод и результат:

```text
<сообщения компиляции>; exit status = 0
```

## Шаг 14. Выполнить этап сборки

```bash
make check
```

Ожидаемый вывод и результат:

```text
Testsuite summary ...
TOTAL: <N>  PASS: <N>  FAIL: 0
```

make check завершился с exit code 0.

config.log сохранен для последующего анализа.

## Шаг 15. Выполнить этап сборки

Только после тестов установите файлы в /usr/local, обновите cache библиотек и проведите локальный тест. Выполните один этап сборки или проверки зависимостей и переходите дальше только при нулевом exit status.

```bash
sudo make install
```

Ожидаемый вывод и результат:

```text
<сообщения компиляции>; exit status = 0
```

## Шаг 16. Обновить кэш динамических библиотек

```bash
sudo ldconfig
```

## Шаг 17. Запустить или проверить iperf3

Запустите или проверьте только указанную учебную программу; параметры ограничивают режим, адрес или длительность нагрузки.

```bash
/usr/local/bin/iperf3 --version
```

Ожидаемый вывод и результат:

```text
iperf 3.<версия> ...
```

## Шаг 18. Проверить библиотеки программы

```bash
ldd /usr/local/bin/iperf3
```

Ожидаемый вывод и результат:

```text
<library> => <path> ...
Строк not found нет.
```

## Шаг 19. Запустить временный unit

Команда обращается к systemd. enable управляет автозапуском, --now также меняет текущее состояние, status/show читают фактические свойства, reload применяет проверенную конфигурацию без полного restart.

```bash
sudo systemd-run --unit=lpic103-iperf-server.service /usr/local/bin/iperf3 -s -1
```

Ожидаемый вывод и результат:

```text
Running as unit: <имя>.service
```

## Шаг 20. Выдержать технологическую паузу

```bash
sleep 1
```

## Шаг 21. Запустить или проверить iperf3

```bash
/usr/local/bin/iperf3 -c 127.0.0.1 -t 3
```

Ожидаемый вывод и результат:

```text
[ ID] Interval Transfer Bitrate
[  5] 0.00-3.00 sec <объем> <скорость> sender/receiver
```

## Шаг 22. Просмотреть журнал службы

Выберите журнал нужного unit и ограничьте временной диапазон, чтобы связать сообщение с только что выполненным действием.

```bash
sudo journalctl -u lpic103-iperf-server.service --no-pager
```

Ожидаемый вывод и результат:

```text
... <unit>[PID]: <сообщение, относящееся к текущему действию> ...
```

Клиент показывает measured throughput и exit code 0.

ldd не выводит not found.
