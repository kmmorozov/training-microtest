# Лабораторная работа 13. NFSv4 export с root_squash и согласованными UID/GID

[Подготовка, пакеты, полные конфиги и уточнения](README.md) · [Общие материалы и ключи](../../PREPARATION.md)

Ниже все шаги руководства лабораторных v4 от 10.08.2026 с сохраненными
командами и ожидаемыми результатами. Сначала выполните подготовку в README:
она определяет адреса, значения переменных и различия ОС. Команды выполняются
по одной, на указанной машине; альтернативные ветки ОС не выполняются вместе.
В командах по умолчанию X=10/Y=20/Z=30, lab NIC=enp0s8, зоны internal/external/public.
Их необходимо сопоставить с реальными NIC/zone по README. Имена unit и web-user
по умолчанию Rocky; для Debian/Ubuntu используйте соответствия из README.
Выводы — образцы, а не протокол запуска на вашей ВМ.

Цель лабораторной работы: экспортировать каталог NFSv4, смонтировать его на клиенте и доказать влияние identity mapping и root_squash.

Стенд: NFS-сервер 192.168.10.20 и клиент 192.168.10.30; на обоих создан lpic103-nfs с одинаковыми UID/GID. X заменяется фактическим номером подсети.

Сценарий: Linux-клиент подключает NFSv4-ресурс. На сервере и клиенте согласуются UID/GID, а root_squash не позволяет клиентскому root обходить права.

Планируемый результат: обычный пользователь с согласованным UID записывает файл, client root не становится server root, export и mount подтверждены штатными средствами.

## Ограничения и безопасность

Важно: не используйте no_root_squash для этой работы.

Важно: открывайте NFS только лабораторной подсети 192.168.10.0/24.

## Ход выполнения

## Шаг 1. Создать группу

**Зачем: NFS передает числовые UID/GID; одинаковое имя с разными номерами не дает одинаковые права. Измените одну учетную запись или группу; параметры UID/GID, shell и членство определяют будущую модель доступа.**

```bash
getent group lpic103-nfs >/dev/null || sudo groupadd -g 2103 lpic103-nfs
```

## Шаг 2. Создать учетную запись

**Зачем: Создаем пользователя с согласованными UID/GID, чтобы NFS-клиент и сервер одинаково интерпретировали владельцев файлов.**

```bash
getent passwd lpic103-nfs >/dev/null || sudo useradd -u 2103 -g 2103 -m lpic103-nfs
```

## Шаг 3. Проверить UID, GID и группы

**Зачем: Проверьте фактические UID, GID и дополнительные группы пользователя, от которых зависят разрешения сервиса.**

```bash
id lpic103-nfs
```

Ожидаемый вывод и результат:

```text
uid=<UID>(<user>) gid=<GID>(<group>) groups=...
```

## Шаг 4. Создать каталог с заданными правами

**Зачем: Создаем серверный каталог экспорта с заданными владельцем и группой, чтобы учебный пользователь мог записывать данные по NFS.**

```bash
# Только на сервере
sudo install -d -o lpic103-nfs -g lpic103-nfs -m 2770 /srv/nfs/lpic103-data
```

id на обеих ВМ показывает UID/GID 2103.

## Шаг 5. Установить требуемые пакеты

**Зачем: Устанавливаем серверные и клиентские NFS-утилиты в RHEL-подобной ОС, чтобы экспортировать каталог и подключить его с клиента.**

```bash
# На сервере и клиенте RHEL-like
sudo dnf install -y nfs-utils
```

## Шаг 6. Обновить метаданные пакетов

**Зачем: Обновите локальные метаданные репозиториев до установки пакетов; это действие не устанавливает и не обновляет сами пакеты.**

```bash
# Debian/Ubuntu
sudo apt update
```

## Шаг 7. Установить требуемые пакеты

**Зачем: Устанавливаем серверную часть NFS в Debian/Ubuntu; клиентские пакеты не заменяют службу экспорта.**

```bash
# Только на Debian/Ubuntu-сервере
sudo apt install -y nfs-kernel-server
```

## Шаг 8. Установить NFS-клиент в Debian/Ubuntu

**Зачем: Пакет nfs-common содержит mount.nfs и клиентские утилиты; серверный пакет на клиенте не требуется.**

```bash
# Только на Debian/Ubuntu-клиенте
sudo apt install -y nfs-common
```

## Шаг 9. Изменить конфигурацию /etc/exports.d/lpic103.exports

**Зачем: Определяем экспорт, допустимую клиентскую подсеть и правила доступа, чтобы сервер предоставлял только учебный каталог.**

```bash
sudoedit /etc/exports.d/lpic103.exports
```

Содержимое редактируемого файла (полный комментированный вариант находится рядом):

```text
# 192.168.10.0/24 — подсеть клиентов NFS

/srv/nfs/lpic103-data 192.168.10.0/24(rw,sync,root_squash,no_subtree_check)
```

## Шаг 10. Применить или проверить NFS export

**Зачем: Применяем определения экспортов, чтобы изменения файла конфигурации стали доступны NFS-клиентам.**

```bash
sudo exportfs -rav
```

Ожидаемый вывод и результат:

```text
<export-path> <client-network>
```

## Шаг 11. Применить или проверить NFS export

**Зачем: Проверяем действующие экспорты и их опции, чтобы убедиться в применении настроек и сохранении root_squash.**

```bash
sudo exportfs -v
```

Ожидаемый вывод и результат:

```text
<export-path> <client-network>
```

## Шаг 12. Включить автозапуск службы

**Зачем: Запускаем NFS-сервер и включаем его автозапуск для публикации подготовленного экспорта.**

```bash
sudo systemctl enable --now nfs-server
```

Ожидаемый вывод и результат:

```text
Created symlink ... (при первом включении); exit status = 0
```

## Шаг 13. Изменить или проверить правило firewall

**Зачем: Сохраняем разрешение NFS в выбранной внутренней зоне firewalld, ограничивая доступ сетевой политикой стенда.**

```bash
# Выберите firewall-ветку
sudo firewall-cmd --permanent --zone=internal --add-service=nfs
```

## Шаг 14. Изменить или проверить правило firewall

**Зачем: Применяем постоянное разрешение NFS в firewalld, чтобы оно действовало в текущей сетевой политике.**

```bash
# Выберите firewall-ветку
sudo firewall-cmd --reload
```

## Шаг 15. Изменить или проверить правило firewall

**Зачем: Открываем TCP/2049 только учебной подсети в ветке UFW; для выбранного NFSv4 дополнительные RPC-порты не требуются.**

```bash
# 192.168.10.0/24 — подсеть клиентов NFS
# UFW — альтернатива
sudo ufw allow from 192.168.10.0/24 to any port 2049 proto tcp
```

## Шаг 16. Проверить сетевой listener

**Зачем: Проверьте реальный socket, адрес, порт и процесс-владелец; состояние службы само по себе не доказывает наличие listener.**

```bash
sudo ss -lntp | grep ':2049 '
```

Ожидаемый вывод и результат:

```text
LISTEN ... <адрес>:<TCP-порт> ... users:(("<процесс>",pid=<PID>))
```

Export ограничен 192.168.10.0/24; TCP/2049 слушается.

## Шаг 17. Создать каталог с заданными правами

**Зачем: Создаем отдельную клиентскую точку монтирования, чтобы сетевой экспорт не перекрывал системные каталоги.**

```bash
# На клиенте
sudo install -d /mnt/lpic103-nfs
```

## Шаг 18. Подключить файловую систему

**Зачем: Монтируем конкретный экспорт по NFSv4.2, чтобы проверить согласованный протокол и доступ к серверным данным.**

```bash
# 192.168.10.20 — адрес NFS-сервера
sudo mount -t nfs4 -o vers=4.2 192.168.10.20:/srv/nfs/lpic103-data /mnt/lpic103-nfs
```

## Шаг 19. Проверить слой хранения

**Зачем: Проверяем источник, версию NFS и параметры монтирования, чтобы подтвердить работу с сетевым экспортом, а не локальным каталогом.**

```bash
findmnt -T /mnt/lpic103-nfs
```

Ожидаемый вывод и результат:

```text
TARGET SOURCE FSTYPE OPTIONS
<mountpoint> <device> <fstype> ...
```

## Шаг 20. Выполнить проверку от имени заданного пользователя

**Зачем: Записываем файл через NFS от имени согласованного пользователя, чтобы проверить сетевую запись с его реальными UID/GID.**

```bash
sudo -u lpic103-nfs sh -c 'echo user-data > /mnt/lpic103-nfs/user.txt'
```

## Шаг 21. Проверить права и атрибуты

**Зачем: Проверяем числового владельца созданного через NFS файла, чтобы подтвердить согласованность UID/GID клиента и сервера.**

```bash
stat -c '%u:%g %a %n' /mnt/lpic103-nfs/user.txt
```

Ожидаемый вывод и результат:

```text
<владелец>:<группа> <mode> <путь>
```

Файл имеет 2103:2103 и читается на сервере.

## Шаг 22. Выполнить проверку от имени заданного пользователя

**Зачем: Из-за root_squash клиентский UID 0 отображается в anonymous identity. Каталог имеет mode 2770 и не дает записи anonymous user, поэтому операция должна завершиться отказом.**

```bash
sudo sh -c 'echo root-data > /mnt/lpic103-nfs/root.txt' || echo 'Ожидаемый отказ root_squash'
```

Ожидаемый вывод и результат:

```text
Permission denied
Ожидаемый отказ root_squash
```

## Шаг 23. Проверить права и атрибуты

**Зачем: Проверяем числовых владельцев файлов на сервере, чтобы увидеть сопоставление UID/GID и результат root_squash.**

```bash
# На сервере
stat -c '%u:%g %a %n' /srv/nfs/lpic103-data/*
```

Ожидаемый вывод и результат:

```text
<владелец>:<группа> <mode> <путь>
```

## Шаг 24. Просмотреть журнал службы

**Зачем: Выберите журнал нужного unit и ограничьте временной диапазон, чтобы связать сообщение с только что выполненным действием.**

```bash
sudo journalctl -u nfs-server --since '-10 min' --no-pager
```

Ожидаемый вывод и результат:

```text
... <unit>[PID]: <сообщение, относящееся к текущему действию> ...
```

Ни один созданный через client root файл не имеет server UID 0.
