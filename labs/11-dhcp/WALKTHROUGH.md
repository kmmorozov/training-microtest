# Лабораторная работа 11. DHCP: пул, reservation, classless route и проверка клиента

[Подготовка, пакеты, полные конфиги и уточнения](README.md) · [Общие материалы и ключи](../../PREPARATION.md)

Ниже все шаги руководства лабораторных v4 от 10.08.2026 с сохраненными
командами и ожидаемыми результатами. Сначала выполните подготовку в README:
она определяет адреса, значения переменных и различия ОС. Команды выполняются
по одной, на указанной машине; альтернативные ветки ОС не выполняются вместе.
В командах по умолчанию X=10/Y=20/Z=30, lab NIC=enp0s8, зоны internal/external/public.
Их необходимо сопоставить с реальными NIC/zone по README. Имена unit и web-user
по умолчанию Rocky; для Debian/Ubuntu используйте соответствия из README.
Выводы — образцы, а не протокол запуска на вашей ВМ.

**Rocky Linux 10: серверная ветка этого исходного задания относится к ISC DHCP. Полная замена всех серверных шагов на Kea дана в [README](README.md); не устанавливайте здесь dhcp-server.**

Цель лабораторной работы: настроить DHCP только в изолированном сегменте, проверить синтаксис и выдачу lease с базовыми и расширенными options.

Стенд: изолированная сеть без другого DHCP; сервер 192.168.10.1/24 и два клиента с NetworkManager. X и Y заменяются фактическими различными номерами подсетей. Пакет ISC DHCP предоставляет стенд.

Сценарий: в изолированном сегменте развертывается DHCP: динамический пул обслуживает обычных клиентов, reservation закрепляет адрес, а classless route передает маршрут.

Планируемый результат: динамический клиент получает адрес из pool, зарезервированный — фиксированный адрес, DNS и route 192.168.20.0/24 через 192.168.10.1.

## Ограничения и безопасность

Важно: никогда не запускайте DHCP server в сети, где уже есть рабочий DHCP.

Важно: перед стартом привяжите сервис только к лабораторному интерфейсу <lab-iface>.

## Ход выполнения

## Шаг 1. Установить требуемые пакеты

**Зачем: Устанавливаем сервер ISC DHCP только в поддерживаемой legacy-ветке; на Rocky 10 этот этап заменяется установкой Kea по README.**

```bash
# RHEL-like
sudo dnf install -y dhcp-server
```

## Шаг 2. Обновить метаданные пакетов

**Зачем: Обновите локальные метаданные репозиториев до установки пакетов; это действие не устанавливает и не обновляет сами пакеты.**

```bash
# Debian/Ubuntu — альтернатива
sudo apt update
```

## Шаг 3. Установить требуемые пакеты

**Зачем: Устанавливаем ISC DHCP в поддерживаемой Debian/Ubuntu-ветке исходной лабораторной; на Rocky 10 используется инструкция Kea из README.**

```bash
# Debian/Ubuntu — альтернатива
sudo apt install -y isc-dhcp-server
```

## Шаг 4. Проверить сетевую конфигурацию

**Зачем: Проверяем статический адрес серверного интерфейса до запуска DHCP, чтобы он соответствовал обслуживаемой подсети.**

```bash
ip -br address show enp0s8
```

Ожидаемый вывод и результат:

```text
<интерфейс> UP <адрес>/<prefix>
```

## Шаг 5. Проверить сетевой listener

**Зачем: Проверяем отсутствие другого DHCP-listener перед запуском учебного сервера, чтобы избежать конфликта порта и конкурирующей выдачи адресов.**

```bash
sudo ss -lunp 'sport = :67'
```

Ожидаемый вывод и результат:

```text
До запуска DHCP-службы команда не выводит UDP/67 listener.
```

<lab-iface> имеет 192.168.10.1/24, другого listener UDP/67 нет.

## Шаг 6. Определить MAC-адрес зарезервированного клиента

**Зачем: Скопируйте значение link/ether физического или закрепленного MAC-адреса профиля. Если NetworkManager рандомизирует MAC, reservation должна использовать фактический адрес DHCP-запроса.**

```bash
# На втором, зарезервированном клиенте
ip link show enp0s8
```

Ожидаемый вывод и результат:

```text
link/ether <MAC-клиента-2> brd ff:ff:ff:ff:ff:ff
```

## Шаг 7. Настроить /etc/dhcp/dhcpd.conf

**Зачем: range задает динамический pool, host — reservation по MAC. Для RFC 3442 option 121 кодируются default route и маршрут в удаленную сеть: длина prefix, значимые байты сети и адрес gateway. Поддерживающий option 121 клиент игнорирует отдельный option routers, поэтому default route включен в тот же массив.**

```bash
sudoedit /etc/dhcp/dhcpd.conf
```

Содержимое редактируемого файла (полный комментированный вариант находится рядом):

```text
# X и Y замените номерами разных подсетей:
# 192.168.10.1 — DHCP-сервер/шлюз; 192.168.10.53 — DNS;
# 192.168.10.60 — reserved client; 192.168.20.0/24 — удаленная сеть.
option rfc3442-classless-static-routes code 121 = array of unsigned integer 8;
authoritative;
default-lease-time 600;
max-lease-time 3600;
option domain-name "example.test";
option domain-name-servers 192.168.10.53;
subnet 192.168.10.0 netmask 255.255.255.0 {
  range 192.168.10.100 192.168.10.150;
  option routers 192.168.10.1;
  option subnet-mask 255.255.255.0;
  option rfc3442-classless-static-routes 0, 192, 168, X, 1,
                                           24, 192, 168, Y, 192, 168, X, 1;
}
host reserved-client {
  hardware ethernet <MAC-клиента-2>;
  fixed-address 192.168.10.60;
}
```

## Шаг 8. Проверить конфигурацию DHCP

**Зачем: dhcpd -t разбирает указанный файл без запуска DHCP listener.**

```bash
sudo dhcpd -t -cf /etc/dhcp/dhcpd.conf
```

Ожидаемый вывод и результат:

```text
Синтаксических ошибок нет; команда завершается с exit status = 0.
```

dhcpd -t не выводит ошибок.

## Шаг 9. Привязать DHCP-службу к лабораторному интерфейсу

**Зачем: Ограничиваем DHCP-сервер учебным интерфейсом, чтобы он не раздавал адреса в управляющую или рабочую сеть; актуальный способ для ОС указан в README и ISC-DHCP.md.**

```bash
# RHEL-like
sudoedit /etc/sysconfig/dhcpd
```

Содержимое редактируемого файла (полный комментированный вариант находится рядом):

```text
DHCPDARGS="<lab-iface>"
# Debian/Ubuntu — альтернатива
sudoedit /etc/default/isc-dhcp-server
INTERFACESv4="<lab-iface>"
```

## Шаг 10. Включить и запустить DHCP-службу

**Зачем: Запускаем выбранную службу ISC DHCP и включаем автозапуск в поддерживаемой ОС; для Rocky 10 вместо этого выполняем ветку Kea из README.**

```bash
# RHEL-like
sudo systemctl enable --now dhcpd.service
# Debian/Ubuntu — альтернатива
sudo systemctl enable --now isc-dhcp-server.service
```

## Шаг 11. Проверить состояние DHCP-службы

**Зачем: Проверяем запуск службы ISC DHCP и отсутствие ошибок конфигурации; состояние Kea в Rocky 10 проверяется по README.**

```bash
# RHEL-like
systemctl status dhcpd.service --no-pager
# Debian/Ubuntu — альтернатива
systemctl status isc-dhcp-server.service --no-pager
```

Ожидаемый вывод и результат:

```text
Active: active (running); Loaded: loaded (...; enabled).
```

## Шаг 12. Проверить сетевой listener

**Зачем: Проверяем наличие UDP-listener DHCP на серверном порту 67, чтобы отличить активный unit от реально открытого сокета.**

```bash
sudo ss -lunp 'sport = :67'
```

Ожидаемый вывод и результат:

```text
UNCONN ... <адрес>:<UDP-порт> ... users:(("<процесс>",pid=<PID>))
```

## Шаг 13. Просмотреть журнал службы

**Зачем: Выберите журнал нужного unit и ограничьте временной диапазон, чтобы связать сообщение с только что выполненным действием.**

```bash
# RHEL-like
journalctl -u dhcpd.service --since '-5 min' --no-pager
# Debian/Ubuntu — альтернатива
journalctl -u isc-dhcp-server.service --since '-5 min' --no-pager
```

Ожидаемый вывод и результат:

```text
... <unit>[PID]: <сообщение, относящееся к текущему действию> ...
```

UDP/67 слушается на лабораторном интерфейсе.

## Шаг 14. Проверить или изменить сетевой профиль

**Зачем: Определяем профиль учебного интерфейса клиента, чтобы переподключить только его, не отключая управляющую сеть.**

```bash
nmcli connection show
```

Ожидаемый вывод и результат:

```text
<профиль/устройство> <состояние> <параметры>
```

## Шаг 15. Подтвердить административные полномочия

**Зачем: Заранее подтвердите sudo-полномочия, чтобы запрос пароля не прервал фоновый захват трафика.**

```bash
sudo -v
```

## Шаг 16. Ограничить время диагностической команды

**Зачем: Записываем DHCP-обмен на учебном интерфейсе, чтобы проследить выдачу аренды и переданные сервером опции.**

```bash
sudo timeout 20 tcpdump -l -ni enp0s8 -c 12 'udp port 67 or udp port 68' > /tmp/lpic103-dhcp.pcap.txt &
```

Ожидаемый вывод и результат:

```text
<вывод ограниченной по времени команды>; exit status 0/124 согласно сценарию
```

## Шаг 17. Задать переменную текущего сеанса

**Зачем: Сохраняем PID захвата DHCP, чтобы дождаться завершения записи обмена до разбора пакетов.**

```bash
CAPTURE_PID=$!
```

## Шаг 18. Проверить или изменить сетевой профиль

**Зачем: Деактивируем только учебное клиентское соединение, чтобы затем проверить новое получение сетевых параметров по DHCP.**

```bash
sudo nmcli connection down lpic103-dhcp-client
```

Ожидаемый вывод и результат:

```text
<профиль/устройство> <состояние> <параметры>
```

## Шаг 19. Проверить или изменить сетевой профиль

**Зачем: Повторно активируем учебное соединение, инициируя получение адреса и опций от DHCP-сервера.**

```bash
sudo nmcli connection up lpic103-dhcp-client
```

Ожидаемый вывод и результат:

```text
<профиль/устройство> <состояние> <параметры>
```

## Шаг 20. Дождаться фонового процесса

**Зачем: Дожидаемся завершения захвата, чтобы разбирать полный записанный обмен, а не промежуточный файл.**

```bash
wait "$CAPTURE_PID" || true
```

## Шаг 21. Сформировать или вывести контрольные данные

**Зачем: Читаем DHCP-пакеты и сопоставляем сообщения клиента и сервера с выданной арендой.**

```bash
cat /tmp/lpic103-dhcp.pcap.txt
```

## Шаг 22. Проверить сетевую конфигурацию

**Зачем: Проверяем адрес на учебном интерфейсе, чтобы подтвердить применение аренды операционной системой клиента.**

```bash
ip -br address show enp0s8
```

Ожидаемый вывод и результат:

```text
<интерфейс> UP <адрес>/<prefix>
```

## Шаг 23. Проверить сетевую конфигурацию

**Зачем: Проверяем полученные маршруты, включая classless static routes, чтобы проверить действие DHCP option 121.**

```bash
ip route
```

Ожидаемый вывод и результат:

```text

```

## Шаг 24. Проверить параметры DNS клиента

**Зачем: Проверяем фактически назначенные DNS-серверы, чтобы подтвердить применение DHCP-опций, а не только выдачу IP-адреса.**

```bash
resolvectl status enp0s8 2>/dev/null || nmcli device show enp0s8
```

Клиент 1 получил pool address, клиент 2 — 192.168.10.60; route присутствует.
