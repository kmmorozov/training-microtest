# Лабораторная работа 12. Базовый файловый ресурс Samba с групповой моделью доступа

[Подготовка, пакеты, полные конфиги и уточнения](README.md) · [Общие материалы и ключи](../../PREPARATION.md)

Ниже все шаги руководства лабораторных v4 от 10.08.2026 с сохраненными
командами и ожидаемыми результатами. Сначала выполните подготовку в README:
она определяет адреса, значения переменных и различия ОС. Команды выполняются
по одной, на указанной машине; альтернативные ветки ОС не выполняются вместе.
В командах по умолчанию X=10/Y=20/Z=30, lab NIC=enp0s8, зоны internal/external/public.
Их необходимо сопоставить с реальными NIC/zone по README. Имена unit и web-user
по умолчанию Rocky; для Debian/Ubuntu используйте соответствия из README.
Выводы — образцы, а не протокол запуска на вашей ВМ.

Цель лабораторной работы: настроить отдельный SMB share, связать Samba-учетную запись с UNIX-user/group и проверить разрешенные и запрещенные операции.

Стенд: Samba-сервер 192.168.10.20 и Linux-клиент с smbclient; DNS-имя files.example.test подготовлено. X заменяется фактическим номером подсети.

Сценарий: команде нужен общий файловый ресурс Samba: участники группы могут читать и изменять файлы, а посторонний пользователь получает отказ.

Планируемый результат: пользователь lpic103-alice читает и пишет в share team, а аутентифицированный lpic103-bob вне разрешенной группы получает отказ; testparm и smbclient подтверждают конфигурацию.

## Ограничения и безопасность

Важно: Samba password не заменяет UNIX account: обе сущности должны существовать.

Важно: не делайте share world-writable и не используйте guest ok для учебного группового ресурса.

## Ход выполнения

## Шаг 1. Установить требуемые пакеты

**Зачем: Сначала установите пакеты, создайте UNIX identity и каталог с setgid, чтобы новые файлы наследовали группу. Установите пакеты только для выбранного семейства ОС. Ключ -y подтверждает пакетную транзакцию без дополнительного запроса.**

```bash
# RHEL-like
sudo dnf install -y samba samba-client policycoreutils-python-utils
```

## Шаг 2. Обновить метаданные пакетов

**Зачем: Обновите локальные метаданные репозиториев до установки пакетов; это действие не устанавливает и не обновляет сами пакеты.**

```bash
# Debian/Ubuntu
sudo apt update
```

## Шаг 3. Установить требуемые пакеты

**Зачем: Устанавливаем Samba-сервер и клиентскую утилиту в Debian/Ubuntu для настройки ресурса и сквозной проверки SMB.**

```bash
# Debian/Ubuntu
sudo apt install -y samba smbclient
```

## Шаг 4. Создать группу

**Зачем: Создаем группу доступа к SMB-ресурсу, чтобы управлять разрешениями через членство пользователей.**

```bash
sudo groupadd -f lpic103-smb
```

## Шаг 5. Создать учетную запись

**Зачем: Создаем локальную учетную запись без интерактивного входа для сопоставления Samba-пользователя с UNIX-правами.**

```bash
getent passwd lpic103-alice >/dev/null || sudo useradd -M -s /usr/sbin/nologin -G lpic103-smb lpic103-alice
```

## Шаг 6. Создать тестового пользователя вне разрешенной группы

**Зачем: Пользователь lpic103-bob существует в UNIX, но не входит в lpic103-smb. Это позволит отделить отказ valid users от ошибки отсутствующей учетной записи.**

```bash
getent passwd lpic103-bob >/dev/null || sudo useradd -M -s /usr/sbin/nologin lpic103-bob
```

## Шаг 7. Создать каталог с заданными правами

**Зачем: Создаем общий каталог с ограниченным групповым доступом и наследованием группы для новых объектов.**

```bash
sudo install -d -o root -g lpic103-smb -m 2770 /srv/samba/lpic103-team
```

## Шаг 8. Зарегистрировать SELinux-контекст ресурса

**Зачем: На RHEL-like с enforcing SELinux одного UNIX mode недостаточно. Постоянное правило fcontext назначает ресурсу тип samba_share_t и переживает relabel.**

```bash
if command -v getenforce >/dev/null && [ "$(getenforce)" = Enforcing ]; then
  sudo semanage fcontext -a -t samba_share_t '/srv/samba/lpic103-team(/.*)?'
else
  echo 'SELinux не находится в enforcing mode; шаг не требуется'
fi
```

## Шаг 9. Применить SELinux-контекст ресурса

**Зачем: restorecon применяет сохраненное правило к существующему каталогу и файлам. Команда chcon здесь не используется, потому что ее изменение непостоянно.**

```bash
if command -v getenforce >/dev/null && [ "$(getenforce)" = Enforcing ]; then
  sudo restorecon -Rv /srv/samba/lpic103-team
else
  echo 'SELinux не находится в enforcing mode; шаг не требуется'
fi
```

## Шаг 10. Изменить учетные данные Samba

**Зачем: Создаем Samba-пароль существующему UNIX-пользователю: наличие локальной учетной записи само по себе не разрешает SMB-аутентификацию.**

```bash
sudo smbpasswd -a lpic103-alice
```

Ожидаемый вывод и результат:

```text
Added user <user>.
```

id показывает группу lpic103-smb; пароль Samba задан отдельно.

## Шаг 11. Создать Samba-учетную запись тестового пользователя

**Зачем: Задайте отдельный учебный пароль. Аутентификация lpic103-bob должна пройти, после чего ресурс [team] отклонит его из-за valid users.**

```bash
sudo smbpasswd -a lpic103-bob
```

Ожидаемый вывод и результат:

```text
Added user lpic103-bob.
```

## Шаг 12. Изменить конфигурацию /etc/samba/smb.conf

**Зачем: valid users ограничивает вход группой, force group сохраняет общую группу, create/directory mask не расширяют права others.**

Установите полный файл для этого этапа по [инструкции подготовки](README.md).
Она заменяет редактирование неполного блока из исходного пособия.

```bash
sudo install -m 0644 labs/12-samba/smb.conf /etc/samba/smb.conf
sudo testparm -s
```

## Шаг 13. Проверить конфигурацию Samba

**Зачем: testparm проверяет синтаксис и показывает effective-параметры ресурса до запуска службы.**

```bash
sudo testparm -s
```

Ожидаемый вывод и результат:

```text
Loaded services file OK; в effective-конфигурации присутствует ресурс [team].
```

## Шаг 14. Включить автозапуск службы

**Зачем: Запускаем службу Samba и включаем автозапуск для обслуживания клиентских SMB-подключений.**

```bash
sudo systemctl enable --now smb
```

Ожидаемый вывод и результат:

```text
Created symlink ... (при первом включении); exit status = 0
```

## Шаг 15. Перечитать конфигурацию службы

**Зачем: Применяем проверенную конфигурацию Samba без полной остановки службы, чтобы новые подключения использовали настройки ресурса.**

```bash
sudo systemctl reload smb
```

## Шаг 16. Изменить или проверить правило firewall

**Зачем: Сохраняем разрешение Samba в выбранной внутренней зоне firewalld, чтобы ресурс был доступен учебным клиентам.**

```bash
# Выберите firewall-ветку
sudo firewall-cmd --permanent --zone=internal --add-service=samba
```

## Шаг 17. Изменить или проверить правило firewall

**Зачем: Применяем постоянные правила firewalld, чтобы разрешение доступа к SMB начало действовать.**

```bash
# Выберите firewall-ветку
sudo firewall-cmd --reload
```

## Шаг 18. Изменить или проверить правило firewall

**Зачем: Разрешаем TCP/445 только учебным SMB-клиентам в альтернативной ветке UFW.**

```bash
# 192.168.10.0/24 — подсеть клиентов Samba
# UFW — альтернатива
sudo ufw allow from 192.168.10.0/24 to any port 445 proto tcp
```

## Шаг 19. Проверить сетевой listener

**Зачем: Проверьте реальный socket, адрес, порт и процесс-владелец; состояние службы само по себе не доказывает наличие listener.**

```bash
sudo ss -lntp | grep -E ':(139|445) '
```

Ожидаемый вывод и результат:

```text
LISTEN ... <адрес>:<TCP-порт> ... users:(("<процесс>",pid=<PID>))
```

testparm без ошибок; TCP/445 слушается.

## Шаг 20. Проверить ресурс Samba

**Зачем: Сначала перечислите shares, затем создайте и прочитайте файл через SMB, не напрямую через /srv. Выполните одну прикладную проверку сервиса и интерпретируйте ответ протокола, а не только exit status процесса.**

```bash
smbclient -L //files.example.test -U lpic103-alice
```

Ожидаемый вывод и результат:

```text
Sharename ... или put/get completed; для запрещенного пользователя — NT_STATUS_ACCESS_DENIED
```

## Шаг 21. Сформировать или вывести контрольные данные

**Зачем: Создаем файл с известным содержимым для сквозной проверки записи и чтения через SMB.**

```bash
echo 'samba test' > /tmp/lpic103-smb.txt
```

## Шаг 22. Проверить ресурс Samba

**Зачем: Загружаем файл на ресурс и скачиваем обратно, чтобы проверить аутентификацию, права записи и чтение по SMB.**

```bash
smbclient //files.example.test/team -U lpic103-alice -c 'put /tmp/lpic103-smb.txt probe.txt; ls; get probe.txt /tmp/lpic103-smb-read.txt'
```

Ожидаемый вывод и результат:

```text
Sharename ... или put/get completed; для запрещенного пользователя — NT_STATUS_ACCESS_DENIED
```

## Шаг 23. Сформировать или вывести контрольные данные

**Зачем: Проверяем содержимое скачанного файла, чтобы подтвердить передачу данных, а не только успешное подключение к ресурсу.**

```bash
cat /tmp/lpic103-smb-read.txt
```

## Шаг 24. Проверить права и атрибуты

**Зачем: Проверяем владельца и права файла на сервере после загрузки по SMB, чтобы связать сетевой доступ с UNIX-разрешениями.**

```bash
stat /srv/samba/lpic103-team/probe.txt
```

Ожидаемый вывод и результат:

```text
<владелец>:<группа> <mode> <путь>
```

Файл прочитан, group=lpic103-smb, others не имеют write.

## Шаг 25. Проверить ресурс Samba

**Зачем: Попытка неразрешенного user должна быть отклонена сервером, а не только клиентским cache credentials. Выполните одну прикладную проверку сервиса и интерпретируйте ответ протокола, а не только exit status процесса.**

```bash
smbclient //files.example.test/team -U lpic103-bob -c ls || echo 'Доступ к team ожидаемо отклонен'
```

Ожидаемый вывод и результат:

```text
NT_STATUS_ACCESS_DENIED
Доступ к team ожидаемо отклонен
```

## Шаг 26. Просмотреть журнал службы

**Зачем: Выберите журнал нужного unit и ограничьте временной диапазон, чтобы связать сообщение с только что выполненным действием.**

```bash
sudo journalctl -u smb --since '-10 min' --no-pager
```

Ожидаемый вывод и результат:

```text
... <unit>[PID]: <сообщение, относящееся к текущему действию> ...
```

Посторонний user не получил список файлов.
