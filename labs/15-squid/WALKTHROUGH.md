# Лабораторная работа 15. Forward proxy Squid: ACL, запрет домена и журнал запроса

[Подготовка, пакеты, полные конфиги и уточнения](README.md) · [Общие материалы и ключи](../../PREPARATION.md)

Ниже все шаги руководства лабораторных v4 от 10.08.2026 с сохраненными
командами и ожидаемыми результатами. Сначала выполните подготовку в README:
она определяет адреса, значения переменных и различия ОС. Команды выполняются
по одной, на указанной машине; альтернативные ветки ОС не выполняются вместе.
В командах по умолчанию X=10/Y=20/Z=30, lab NIC=enp0s8, зоны internal/external/public.
Их необходимо сопоставить с реальными NIC/zone по README. Имена unit и web-user
по умолчанию Rocky; для Debian/Ubuntu используйте соответствия из README.
Выводы — образцы, а не протокол запуска на вашей ВМ.

Цель лабораторной работы: настроить явный HTTP proxy для лабораторной сети, разрешить нужный источник и заблокировать отдельный тестовый домен.

Стенд: Squid-сервер 192.168.10.40 и клиент 192.168.10.100; DNS стенда разрешает allowed.example.test и blocked.example.test. X заменяется фактическим номером подсети.

Сценарий: клиенты учебной сети выходят через Squid. Разрешается сеть labnet, один тестовый домен блокируется, а результат подтверждается ответом proxy и журналом.

Планируемый результат: разрешенный запрос проходит через TCP/3128, blocked.example.test получает deny, а access.log объясняет оба результата.

## Ограничения и безопасность

Важно: порядок http_access важен: Squid применяет первое совпавшее правило.

Важно: не создавайте open proxy; разрешайте только 192.168.10.0/24 и блокируйте остальные источники.

## Ход выполнения

## Шаг 1. Установить требуемые пакеты

Установите proxy package своей ОС. До ACL проверьте версию, unit и отсутствие неожиданного TCP/3128 listener. Установите пакеты только для выбранного семейства ОС. Ключ -y подтверждает пакетную транзакцию без дополнительного запроса.

```bash
# RHEL-like
sudo dnf install -y squid
```

## Шаг 2. Обновить метаданные пакетов

Обновите локальные метаданные репозиториев до установки пакетов; это действие не устанавливает и не обновляет сами пакеты.

```bash
# Debian/Ubuntu — альтернатива
sudo apt update
```

## Шаг 3. Установить требуемые пакеты

Установите пакеты только для выбранного семейства ОС. Ключ -y подтверждает пакетную транзакцию без дополнительного запроса.

```bash
# Debian/Ubuntu — альтернатива
sudo apt install -y squid
```

## Шаг 4. Проверить или применить конфигурацию Squid

Проверьте синтаксис или effective-конфигурацию службы до ее reload; при ошибке текущая служба не изменяется.

```bash
squid -v | head
```

## Шаг 5. Настроить /etc/squid/squid.conf

Сначала объявляются ACL, затем запрет домена, разрешение labnet и финальный deny all.

```bash
sudoedit /etc/squid/squid.conf
```

Содержимое редактируемого файла (полный комментированный вариант находится рядом):

```text
# 192.168.10.40 — Squid-сервер; 192.168.10.0/24 — подсеть клиентов.
http_port 192.168.10.40:3128
acl labnet src 192.168.10.0/24
acl blocked dstdomain .blocked.example.test
http_access deny blocked
http_access allow labnet
http_access deny all
```

## Шаг 6. Проверить конфигурацию Squid

Проверка выполняется до запуска или reload, поэтому ошибочная конфигурация не заменяет текущую рабочую.

```bash
sudo squid -k parse
```

Ожидаемый вывод и результат:

```text
Синтаксических ошибок нет; команда завершается с exit status = 0.
```

## Шаг 7. Включить автозапуск службы

```bash
sudo systemctl enable --now squid.service
```

Ожидаемый вывод и результат:

```text
Created symlink ... (при первом включении); exit status = 0
```

## Шаг 8. Проверить или применить конфигурацию Squid

```bash
sudo squid -k reconfigure
```

## Шаг 9. Изменить или проверить правило firewall

Измените или прочитайте одно правило сетевой политики. Источник, назначение, протокол и порт должны быть ограничены учебным сценарием.

```bash
# Выберите firewall-ветку
sudo firewall-cmd --permanent --zone=internal --add-port=3128/tcp
```

## Шаг 10. Изменить или проверить правило firewall

```bash
# Выберите firewall-ветку
sudo firewall-cmd --reload
```

## Шаг 11. Изменить или проверить правило firewall

```bash
# 192.168.10.0/24 — подсеть клиентов Squid
# UFW — альтернатива
sudo ufw allow from 192.168.10.0/24 to any port 3128 proto tcp
```

## Шаг 12. Проверить сетевой listener

```bash
sudo ss -lntp 'sport = :3128'
```

Ожидаемый вывод и результат:

```text
LISTEN ... <адрес>:<TCP-порт> ... users:(("<процесс>",pid=<PID>))
```

squid -k parse успешен, listener привязан к 192.168.10.40.

## Шаг 13. Выполнить прикладной HTTP-запрос

-x явно задает proxy; так результат не зависит от переменных окружения клиента. Отправьте прикладной HTTP/HTTPS-запрос. Параметры --resolve/--cacert проверяют нужный адрес, имя и доверие без отключения TLS-проверок.

```bash
# 192.168.10.40 — адрес Squid-сервера
curl -sS -o /dev/null -w '%{http_code}\n' -x http://192.168.10.40:3128 http://allowed.example.test/
```

Ожидаемый вывод и результат:

```text
200 либо другой ожидаемый код 2xx/3xx разрешенного тестового сайта.
```

## Шаг 14. Выполнить прикладной HTTP-запрос

Отправьте прикладной HTTP/HTTPS-запрос. Параметры --resolve/--cacert проверяют нужный адрес, имя и доверие без отключения TLS-проверок.

```bash
# 192.168.10.40 — адрес Squid-сервера
curl -sS -o /dev/null -w '%{http_code}\n' -x http://192.168.10.40:3128 http://blocked.example.test/
```

Ожидаемый вывод и результат:

```text
403
```

Разрешенный запрос имеет 2xx/3xx; blocked — HTTP 403 от Squid.

## Шаг 15. Отфильтровать диагностический вывод

access.log должен показать client IP, action и destination для каждого запроса.

```bash
sudo tail -n 20 /var/log/squid/access.log
```

## Шаг 16. Просмотреть журнал службы

Выберите журнал нужного unit и ограничьте временной диапазон, чтобы связать сообщение с только что выполненным действием.

```bash
sudo journalctl -u squid.service --since '-10 min' --no-pager
```

Ожидаемый вывод и результат:

```text
... <unit>[PID]: <сообщение, относящееся к текущему действию> ...
```

В журнале есть TCP_DENIED для blocked и разрешающий result для allowed.
