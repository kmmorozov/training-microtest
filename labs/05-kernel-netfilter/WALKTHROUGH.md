# Лабораторная работа 05. Модуль ядра, conntrack и счетчик netfilter

[Подготовка, пакеты, полные конфиги и уточнения](README.md) · [Общие материалы и ключи](../../PREPARATION.md)

Ниже все шаги руководства лабораторных v4 от 10.08.2026 с сохраненными
командами и ожидаемыми результатами. Сначала выполните подготовку в README:
она определяет адреса, значения переменных и различия ОС. Команды выполняются
по одной, на указанной машине; альтернативные ветки ОС не выполняются вместе.
В командах по умолчанию X=10/Y=20/Z=30, lab NIC=enp0s8, зоны internal/external/public.
Их необходимо сопоставить с реальными NIC/zone по README. Имена unit и web-user
по умолчанию Rocky; для Debian/Ubuntu используйте соответствия из README.
Выводы — образцы, а не протокол запуска на вашей ВМ.

Цель лабораторной работы: безопасно загрузить тестовый модуль, сделать его параметр воспроизводимым, а затем сопоставить тестовое TCP-соединение с conntrack и nft counter.

Стенд: одна изолированная Linux-ВМ с пакетами conntrack-tools/nftables и Python 3.

Сценарий: нужно проследить путь TCP-запроса: загрузить тестовый модуль ядра, увидеть соединение в conntrack и подтвердить срабатывание счетчика nftables.

Планируемый результат: dummy0 создан модулем dummy, TCP/8080 подтвержден через ss и conntrack, а счетчик отдельной nftables-таблицы увеличивается после запроса.

## Ограничения и безопасность

Важно: используйте только модуль dummy: он не управляет реальным устройством.

Важно: не изменяйте существующие firewall tables; для счетчика используется отдельная таблица inet lpic103_lab.

## Ход выполнения

## Шаг 1. Показать сведения о модуле ядра

modinfo показывает параметры до загрузки; modprobe учитывает зависимости и потому предпочтительнее insmod. Получите одно наблюдение ядра или примените один параметр; вывод нужен для связи пакета, модуля и состояния системы.

```bash
modinfo dummy | sed -n '1,25p'
```

Ожидаемый вывод и результат:

```text
filename: ...
name: ...
description: ...
```

## Шаг 2. Загрузить модуль ядра

Получите одно наблюдение ядра или примените один параметр; вывод нужен для связи пакета, модуля и состояния системы.

```bash
sudo modprobe dummy numdummies=1
```

## Шаг 3. Проверить загруженные модули

```bash
lsmod | grep '^dummy'
```

Ожидаемый вывод и результат:

```text
<module> <size> <used-by>
```

## Шаг 4. Проверить сетевую конфигурацию

Проверьте один уровень сетевой конфигурации: интерфейс, адрес, маршрут, DNS или профиль соединения.

```bash
ip -details link show dummy0
```

## Шаг 5. Сформировать или вывести контрольные данные

modules-load.d запрашивает загрузку, а modprobe.d задает параметры. Один файл не заменяет другой.

```bash
echo dummy | sudo tee /etc/modules-load.d/lpic103-dummy.conf
```

## Шаг 6. Сформировать или вывести контрольные данные

```bash
echo 'options dummy numdummies=1' | sudo tee /etc/modprobe.d/lpic103-dummy.conf
```

## Шаг 7. Показать итоговую конфигурацию modprobe

```bash
modprobe --showconfig | grep -E '(^| )dummy|numdummies'
```

В effective modprobe config виден options dummy numdummies=1.

## Шаг 8. Запустить временный unit

Создайте короткоживущий HTTP-процесс как transient unit. Это даст конкретный поток для conntrack. Команда обращается к systemd. enable управляет автозапуском, --now также меняет текущее состояние, status/show читают фактические свойства, reload применяет проверенную конфигурацию без полного restart. Адрес 0.0.0.0 привязывает listener ко всем интерфейсам сервера; это не адрес клиента.

```bash
sudo systemd-run --unit=lpic103-http.service /usr/bin/python3 -m http.server 8080 --bind 0.0.0.0
```

Ожидаемый вывод и результат:

```text
Running as unit: <имя>.service
```

## Шаг 9. Выдержать технологическую паузу

```bash
sleep 1
```

## Шаг 10. Проверить сетевой listener

Проверьте реальный socket, адрес, порт и процесс-владелец; состояние службы само по себе не доказывает наличие listener.

```bash
sudo ss -lntp 'sport = :8080'
```

Ожидаемый вывод и результат:

```text
LISTEN ... <адрес>:<TCP-порт> ... users:(("<процесс>",pid=<PID>))
```

## Шаг 11. Выполнить прикладной HTTP-запрос

Отправьте прикладной HTTP/HTTPS-запрос. Параметры --resolve/--cacert проверяют нужный адрес, имя и доверие без отключения TLS-проверок.

```bash
curl --fail http://127.0.0.1:8080/ >/dev/null
```

Ожидаемый вывод и результат:

```text
curl завершается с exit status = 0; тело ответа перенаправлено в указанный файл или /dev/null.
```

curl завершается с exit code 0.

## Шаг 12. Изменить или проверить правило nftables

Временная nft table имеет policy accept и только считает TCP/8080. После запроса найдите тот же поток в conntrack. Измените или прочитайте одно правило сетевой политики. Источник, назначение, протокол и порт должны быть ограничены учебным сценарием.

```bash
sudo nft add table inet lpic103_lab
```

## Шаг 13. Изменить или проверить правило nftables

Измените или прочитайте одно правило сетевой политики. Источник, назначение, протокол и порт должны быть ограничены учебным сценарием.

```bash
sudo nft 'add chain inet lpic103_lab input { type filter hook input priority 10; policy accept; }'
```

## Шаг 14. Изменить или проверить правило nftables

```bash
sudo nft add rule inet lpic103_lab input tcp dport 8080 counter
```

## Шаг 15. Выполнить прикладной HTTP-запрос

```bash
curl --fail http://127.0.0.1:8080/ >/dev/null
```

Ожидаемый вывод и результат:

```text
curl завершается с exit status = 0; тело ответа перенаправлено в указанный файл или /dev/null.
```

## Шаг 16. Изменить или проверить правило nftables

```bash
sudo nft list table inet lpic103_lab
```

Ожидаемый вывод и результат:

```text
<table/chain/rule>; counter packets <N> bytes <N> или успешное завершение с exit status = 0
```

## Шаг 17. Проверить отслеживаемое соединение

```bash
sudo conntrack -L -p tcp 2>/dev/null | grep 'dport=8080' | head
```

Ожидаемый вывод и результат:

```text
tcp ... src=<адрес> dst=<адрес> sport=<порт> dport=<порт> ...
```

## Шаг 18. Применить или проверить параметр ядра

```bash
sysctl net.netfilter.nf_conntrack_count net.netfilter.nf_conntrack_max
```

Ожидаемый вывод и результат:

```text
<параметр> = <значение>
```

nft counter больше нуля.

nf_conntrack_count меньше nf_conntrack_max.
