# Лабораторная работа 04. Базовый запуск Cockpit и ограничение административного доступа

[Подготовка, пакеты, полные конфиги и уточнения](README.md) · [Общие материалы и ключи](../../PREPARATION.md)

Ниже все шаги руководства лабораторных v4 от 10.08.2026 с сохраненными
командами и ожидаемыми результатами. Сначала выполните подготовку в README:
она определяет адреса, значения переменных и различия ОС. Команды выполняются
по одной, на указанной машине; альтернативные ветки ОС не выполняются вместе.
В командах по умолчанию X=10/Y=20/Z=30, lab NIC=enp0s8, зоны internal/external/public.
Их необходимо сопоставить с реальными NIC/zone по README. Имена unit и web-user
по умолчанию Rocky; для Debian/Ubuntu используйте соответствия из README.
Выводы — образцы, а не протокол запуска на вашей ВМ.

Цель лабораторной работы: запустить web-интерфейс администрирования, подтвердить listener/HTTPS и оставить доступ только сети управления.

Стенд: Cockpit-сервер с адресом 192.168.10.10 в сети управления и 192.168.20.10 в пользовательской сети; клиенты 192.168.10.100 и 192.168.20.100. X и Y заменяются фактическими различными номерами подсетей.

Сценарий: Cockpit разворачивается как административная консоль, доступная только из выделенной сети управления, а не со всех сегментов стенда.

Планируемый результат: Cockpit проходит локальную HTTPS-проверку; TCP/9090 доступен из management subnet и недоступен из user subnet.

## Ограничения и безопасность

Важно: не публикуйте административные порты в общую сеть.

Важно: curl -k допустим только для проверки сетевой доступности учебного endpoint; он отключает проверку доверия к сертификату и не подтверждает безопасность TLS.

## Ход выполнения

## Шаг 1. Установить требуемые пакеты

**Зачем: Cockpit использует socket activation: сначала проверяется cockpit.socket, а не постоянно работающий web-процесс. Установите пакеты только для выбранного семейства ОС. Ключ -y подтверждает пакетную транзакцию без дополнительного запроса.**

```bash
# RHEL-like
sudo dnf install -y cockpit
```

## Шаг 2. Обновить метаданные пакетов

**Зачем: Обновите локальные метаданные репозиториев до установки пакетов; это действие не устанавливает и не обновляет сами пакеты.**

```bash
# Debian/Ubuntu
sudo apt update
```

## Шаг 3. Установить требуемые пакеты

**Зачем: Устанавливаем веб-интерфейс администрирования Cockpit из репозитория Debian/Ubuntu для последующей настройки доступа.**

```bash
# Debian/Ubuntu
sudo apt install -y cockpit
```

## Шаг 4. Включить автозапуск службы

**Зачем: Включаем socket activation Cockpit сейчас и при загрузке, чтобы веб-процесс запускался по входящему подключению.**

```bash
sudo systemctl enable --now cockpit.socket
```

Ожидаемый вывод и результат:

```text
Created symlink ... (при первом включении); exit status = 0
```

## Шаг 5. Проверить состояние службы

**Зачем: Проверяем готовность socket activation Cockpit: ожидаем активный socket, даже если веб-процесс еще не запущен.**

```bash
systemctl status cockpit.socket --no-pager
```

Ожидаемый вывод и результат:

```text
Active: active (listening)
Loaded: loaded (...; enabled)
```

## Шаг 6. Проверить сетевой listener

**Зачем: Проверьте реальный socket, адрес, порт и процесс-владелец; состояние службы само по себе не доказывает наличие listener.**

```bash
sudo ss -lntp 'sport = :9090'
```

Ожидаемый вывод и результат:

```text
LISTEN ... <адрес>:<TCP-порт> ... users:(("<процесс>",pid=<PID>))
```

## Шаг 7. Выполнить прикладной HTTP-запрос

**Зачем: Проверяем локальный HTTPS-ответ Cockpit независимо от внешнего firewall; ключ -k отключает проверку сертификата и не доказывает доверие к нему.**

```bash
curl -kI https://127.0.0.1:9090
```

Ожидаемый вывод и результат:

```text
Получены HTTP-заголовки Cockpit с кодом 2xx/3xx; exit status = 0.
```

HTTP status локального ответа зафиксирован.

## Шаг 8. Изменить или проверить правило firewall

**Зачем: Выберите ровно одну ветку firewall. Для firewalld создайте отдельную source-based zone и убедитесь, что cockpit/порт не открыты в общей interface zone. Сначала проверьте runtime-правила двумя клиентами. Измените или прочитайте одно правило сетевой политики. Источник, назначение, протокол и порт должны быть ограничены учебным сценарием.**

```bash
# firewalld: объект zone создается permanent и активируется reload; доступ пока добавляется только runtime
firewall-cmd --get-active-zones
```

Ожидаемый вывод и результат:

```text
success или список zone/source/service/port, соответствующий команде
```

## Шаг 9. Изменить или проверить правило firewall

**Зачем: Создаем отдельную постоянную зону управления, чтобы не смешивать административный доступ с общей интерфейсной политикой.**

```bash
sudo firewall-cmd --permanent --new-zone=lpic103-mgmt
```

## Шаг 10. Изменить или проверить правило firewall

**Зачем: Загружаем постоянную конфигурацию firewalld, чтобы новая зона стала доступна для дальнейших runtime-правил.**

```bash
sudo firewall-cmd --reload
```

## Шаг 11. Изменить или проверить правило firewall

**Зачем: Относим управляющую подсеть к отдельной зоне, чтобы правила доступа Cockpit применялись именно к административным клиентам.**

```bash
# 192.168.10.0/24 — подсеть клиентов административного доступа
sudo firewall-cmd --zone=lpic103-mgmt --add-source=192.168.10.0/24
```

## Шаг 12. Изменить или проверить правило firewall

**Зачем: Открываем порт Cockpit в управляющей зоне для пробной проверки, не предоставляя доступ всем сетям.**

```bash
sudo firewall-cmd --zone=lpic103-mgmt --add-port=9090/tcp
```

## Шаг 13. Изменить или проверить правило firewall

**Зачем: Проверяем все зоны вместе, чтобы обнаружить более широкое разрешение, которое могло бы обойти ограничение управляющей подсетью.**

```bash
sudo firewall-cmd --list-all-zones
```

Ожидаемый вывод и результат:

```text
success или список zone/source/service/port, соответствующий команде
```

## Шаг 14. Изменить или проверить правило firewall

**Зачем: Задаем запрет входящих соединений по умолчанию в ветке UFW, чтобы доступ предоставлялся только явными разрешениями.**

```bash
# UFW: альтернатива firewalld; сохраните console и подставьте фактический SSH port
sudo ufw default deny incoming
```

## Шаг 15. Изменить или проверить правило firewall

**Зачем: Сохраняем SSH-доступ из управляющей подсети перед включением UFW, чтобы не потерять удаленное управление стендом.**

```bash
# 192.168.10.0/24 — подсеть клиентов административного доступа
sudo ufw allow from 192.168.10.0/24 to any port 22 proto tcp
```

## Шаг 16. Изменить или проверить правило firewall

**Зачем: Разрешаем веб-интерфейс Cockpit только управляющей подсети в альтернативной ветке UFW.**

```bash
# 192.168.10.0/24 — подсеть клиентов административного доступа
sudo ufw allow from 192.168.10.0/24 to any port 9090 proto tcp
```

## Шаг 17. Изменить или проверить правило firewall

**Зачем: Включаем подготовленную политику UFW, чтобы правила начали фильтровать трафик; резервная консоль должна оставаться доступной.**

```bash
sudo ufw --force enable
```

## Шаг 18. Изменить или проверить правило firewall

**Зачем: Проверяем активность UFW и итоговые разрешения, чтобы подтвердить применение политики и отсутствие лишнего доступа.**

```bash
sudo ufw status verbose
```

Ожидаемый вывод и результат:

```text
Rule added/updated или Status: active с ожидаемым правилом
```

Клиент 192.168.10.100 открывает endpoint Cockpit.

Клиент из другой подсети получает timeout/refused согласно политике.

## Шаг 19. Изменить или проверить правило firewall

**Зачем: Если выбран firewalld, повторите проверенную source-zone в permanent configuration. Не копируйте весь runtime ruleset вслепую. Измените или прочитайте одно правило сетевой политики. Источник, назначение, протокол и порт должны быть ограничены учебным сценарием.**

```bash
# 192.168.10.0/24 — подсеть клиентов административного доступа
sudo firewall-cmd --permanent --zone=lpic103-mgmt --add-source=192.168.10.0/24
```

## Шаг 20. Изменить или проверить правило firewall

**Зачем: Сохраняем разрешение Cockpit в постоянной конфигурации управляющей зоны, чтобы оно пережило reload и перезагрузку.**

```bash
sudo firewall-cmd --permanent --zone=lpic103-mgmt --add-port=9090/tcp
```

## Шаг 21. Изменить или проверить правило firewall

**Зачем: Убираем общее разрешение Cockpit из интерфейсной зоны, чтобы оно не обходило ограничение по адресу источника.**

```bash
# Выполняйте для фактической interface zone.
if sudo firewall-cmd --permanent --zone=public --query-service=cockpit; then
  sudo firewall-cmd --permanent --zone=public --remove-service=cockpit
else
  echo 'Сервис cockpit в общей interface zone не открыт'
fi
```

## Шаг 22. Изменить или проверить правило firewall

**Зачем: Применяем сохраненные правила заново, чтобы проверить именно постоянную конфигурацию, а не оставшиеся runtime-разрешения.**

```bash
sudo firewall-cmd --reload
```

## Шаг 23. Изменить или проверить правило firewall

**Зачем: Проверяем источники и порты управляющей зоны после reload, чтобы подтвердить сохранение ограничения доступа.**

```bash
sudo firewall-cmd --zone=lpic103-mgmt --list-all
```

Ожидаемый вывод и результат:

```text
success или список zone/source/service/port, соответствующий команде
```

После reload позитивный и негативный тесты не изменились.

## Шаг 24. Проверить доступ из сети управления

**Зачем: Запустите запрос с клиента сети управления. Ключ -k используется только потому, что стенд может иметь недоверенный учебный сертификат; он не проверяет доверие к TLS.**

```bash
# На клиенте управления 192.168.10.100; 192.168.10.10 — адрес Cockpit-сервера
curl -kI --connect-timeout 4 https://192.168.10.10:9090
```

Ожидаемый вывод и результат:

```text
Получен HTTP-ответ Cockpit; TCP-соединение с 192.168.10.10:9090 установлено.
```

## Шаг 25. Проверить запрет из пользовательской сети

**Зачем: Повторите запрос с клиента другой подсети. Успешный HTTP-ответ означает ошибку firewall-политики.**

```bash
# На клиенте 192.168.20.100; 192.168.20.10 — адрес Cockpit-сервера в пользовательской сети
if curl -kfsSI --connect-timeout 4 https://192.168.20.10:9090; then
  echo 'ОШИБКА: доступ из пользовательской сети разрешен'
else
  echo 'Доступ из пользовательской сети ожидаемо заблокирован'
fi
```

Ожидаемый вывод и результат:

```text
Доступ из пользовательской сети ожидаемо заблокирован
```
